# SourceBrief claim ledger

This ledger keeps launch-facing wording tied to current proof. It is intentionally stricter than marketing copy: a claim is safe only when the evidence is current for the named candidate or explicitly labeled historical. The [Core Product Reset](CORE_PRODUCT_RESET.md) additionally requires product surfaces to expose orthogonal generation, review, coverage, freshness, availability, and execution dimensions instead of collapsing structural/deterministic/AI provenance and lifecycle state into one label.

## Status labels

| Status | Meaning |
| --- | --- |
| Implemented | The current source path exists and is named honestly. Code/docs/tests can support implementation wording, but this is not declared-SHA outcome or launch proof. |
| Current | Verified on the declared launch candidate SHA or a newer named SHA. |
| Historical | Real evidence exists, but it was captured on an older commit/run and cannot prove the current candidate by itself. |
| RISK | Mechanically demonstrated, but quality, corpus, provider, UX, or proof gaps remain. |
| Unsupported | Do not use in customer-facing wording. |

## Rule for launch reports

A launch report may use **PASS** only when every claim it repeats is `Current` for the declared SHA and the security/failure-mode gate has passed. `Implemented` supports honest implementation wording only and cannot produce launch PASS. If any claim relies on `Implemented`, `Historical`, or `RISK` evidence, the launch report must use `RISK` with the linked caveat. Unsupported claims must be removed, not caveated.
